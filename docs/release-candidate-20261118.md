## Rollback and remaining limitations

Stop on any baseline, identity, checksum, CI or authorization mismatch. Keep site private, stop builds and freeze writes on runtime failures. Preserve new ledger/history; prefer a reviewed forward fix over dropping columns/tables. Function rollback requires a separately reviewed migration and evidence that no new-policy agreements depend on it; an old app must not run against incompatible new financial behavior. Restore only into an isolated environment after explicit approval, never blindly overwrite the hosted project.

No automatic identity disclosure or visit authorization is introduced: identities remain confidential. A dedicated buyer-consented introduction/visit workflow is not delivered by this candidate. Advanced analytics, external shipment/payment integrations and outbound transactional marketplace notifications are deferred; current operations record external evidence and use existing in-app notifications. Full hosted end-to-end revalidation of the new candidate and current hosted environment readback remain outstanding, not silently marked PASS.
